# Release v0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish fernjo v0.1.0 as a GitHub release on `main` with five installers and `SHA256SUMS`, and bring `dev` back in line with `main`.

**Architecture:** The sequence of step 8 in `Docs/release-checklist.md`: a `release/v0.1.0` branch from `dev` carries the version bump and the docs, a merge-commit PR moves it to `main`, `gh release create` triggers `release.yml` (build, smoke test, publish), and a merge-commit PR brings `main` back into `dev`.

**Tech Stack:** git, `gh`, bash, the repo's gate commands (cargo, pnpm, dotnet for `tools/roadmap.cs`), GitHub Actions (`release.yml`).

**Spec:** `Docs/superpowers/specs/2026-11-18-release-v0.1.0-design.md`

## Global Constraints

- Branch `release/v0.1.0` from `dev`; never commit to `dev` or `main` directly.
- PR `release/v0.1.0` → `main` and PR `main` → `dev` are merged with **"Create a merge commit"** (`gh pr merge <n> --merge`), never squash or rebase.
- No force push, no `--no-verify`, no deleting branches, tags or releases without the owner's decision.
- `tools/check-release-version.sh` accepts only `[v]MAJOR.MINOR.PATCH`; tag `v0.1.0`, `[workspace.package] version` in `Cargo.toml` and `version` in `package.json` must all be `0.1.0`.
- Commits follow Conventional Commits, no attribution lines; stage files selectively (`git add <file>`, never `-A`); after every commit check `git show --stat HEAD` against the expected files.
- CodeQL alerts are dismissed only on the owner's explicit instruction.
- "Done" means each gate command's result is stated; anything not run is marked open.
- Stop rule (owner decision 2026-11-18, steps 2 to 4 are pre-authorised **unless something goes wrong**): stop and report, with no workaround, when a gate command or CI check is red, CodeQL reports a new alert, `git status` or a diff shows something unexpected, the release workflow fails or the attached files are wrong.

## Review Focus

- A stale `Cargo.lock` after the bump makes every `--locked` command and the CI jobs fail: commit the refreshed lock file in the same commit as the version.
- `main` requires the checks `roadmap`, `rust`, `ui`, `tauri-build`, `cargo-deny`, `workflows` and an up-to-date branch (`strict`); a PR that is behind `main` cannot merge.
- `gh release create` publishes at once; between the release event and the end of `release.yml`'s `publish` job the public release has no assets. That window is expected; an empty release after the run is the failure.
- The release run uses the tag's commit on `main`; a version mismatch fails `check-release-version.sh` inside the run, so the check runs locally first.
- The README and roadmap say "released" before the release exists (they ship in the release PR); if the release fails, fix that state before anything else.
- The back-merge PR can conflict only if someone pushed to `dev` meanwhile; then stop and report.

### Task 1: Prepare the release branch and the gate

**Files:**
- Create: `Docs/superpowers/specs/2026-11-18-release-v0.1.0-design.md` (already written, uncommitted), `Docs/superpowers/plans/2026-11-18-release-v0.1.0.md` (this file)
- Modify: `Cargo.toml` (`[workspace.package] version`), `Cargo.lock`, `package.json`, `CHANGELOG.md`, `README.md`, `Docs/roadmap.json`, `Docs/ROADMAP.md` (generated), `Docs/release-checklist.md`

**Interfaces:**
- Consumes: branch `release/v0.1.0` (exists, based on `dev` at `977dab4`, clean apart from the spec and this plan).
- Produces: one pushed branch whose head is the release commit; its hash is used by Tasks 2 and 3.

- [ ] **Step 1: Commit the spec and plan**

`git add Docs/superpowers/specs/2026-11-18-release-v0.1.0-design.md Docs/superpowers/plans/2026-11-18-release-v0.1.0.md`, then `git commit -m "docs: plan release v0.1.0"`; `git show --stat HEAD` lists exactly those two files.

- [ ] **Step 2: Bump the versions**

Set `version = "0.1.0"` in `[workspace.package]` of `Cargo.toml` and `"version": "0.1.0"` in `package.json`. Run `cargo metadata --format-version 1 > /dev/null` (refreshes `Cargo.lock` for the workspace crates; if it does not change the lock file, run `cargo build --workspace` once). Expected: `git diff --stat` shows `Cargo.toml`, `Cargo.lock`, `package.json`, and the lock diff contains only version lines of workspace crates.

- [ ] **Step 3: Verify the version check passes**

Run: `bash tools/check-release-version.sh v0.1.0`
Expected: exit 0 (before Step 2 it exits 1 with a "does not match tag version" error; that is the documented starting state).

- [ ] **Step 4: Update the CHANGELOG**

In `CHANGELOG.md`, turn `## [Unreleased]` into `## [0.1.0] - 2026-11-18`, add a line under it naming the contained milestones (M0 to M6), drop the empty `### Removed` heading at its end, and put a new empty `## [Unreleased]` above it. Expected: `grep -n "^## \[" CHANGELOG.md` prints `[Unreleased]` then `[0.1.0] - 2026-11-18`.

- [ ] **Step 5: Update the README**

Two places say v0.1.0 is not published: the `**Status:**` line (line 7) and the first sentence of the "Install" section (line 28). Reword both for the published release: status names v0.1.0 as released with the GitHub releases page (`https://github.com/benjo-code/fernjo/releases`) as the download place and keeps "v0.2.0 adds RDP"; the Install sentence drops "not published yet. Once it is," and keeps the table. Keep every verification caveat (unsigned, Apple Silicon dmg and `.deb` not run on real hardware). Expected: `grep -n "not published" README.md` prints nothing.

- [ ] **Step 6: Run the gate**

Run each command and note its result (counts, exit code):

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
pnpm install --frozen-lockfile
pnpm test
pnpm lint
cargo deny check
bash tools/check-workflows.sh
bash tools/test-release-scripts.sh
```

Expected: every command exits 0; `cargo test` and `pnpm test` report 0 failed (the live-SSH tests skip locally without the container and count through the CI `rust` job: say so in the result, do not claim them as run).

- [ ] **Step 7: Record the result and mark the release done in the roadmap**

In `Docs/release-checklist.md` add a section "v0.1.0 release commit" with the table of Step 6 commands and their actual results, the head commit it was run on, and the statement that the SSH container tests count through CI. In `Docs/roadmap.json` set the release `0.1.0` entry to `"status": "done"` with `"date": "2026-11-18"` (omit nothing else, no `null`). Then run `dotnet run tools/roadmap.cs -- generate` and `dotnet run tools/roadmap.cs -- check`. Expected: "Roadmap is valid and ROADMAP.md is up to date."

- [ ] **Step 8: Commit and push**

```bash
git add Cargo.toml Cargo.lock package.json CHANGELOG.md README.md Docs/roadmap.json Docs/ROADMAP.md Docs/release-checklist.md
git commit -m "chore(release): v0.1.0"
git push -u origin release/v0.1.0
```

Expected: `git show --stat HEAD` lists exactly those eight files; the push succeeds; `git rev-parse HEAD` is recorded as the release commit.

### Task 2: PR to `main`, checks, merge

**Files:** none (GitHub only).

**Interfaces:**
- Consumes: pushed `release/v0.1.0` from Task 1.
- Produces: `main` at a merge commit that contains the release commit (read its hash with `git rev-parse origin/main` after `git fetch`); the PR number.

- [ ] **Step 1: Open the PR**

`gh pr create --base main --head release/v0.1.0 --title "chore(release): v0.1.0" --body "<what is in it: version bump, CHANGELOG 0.1.0, README, roadmap; evidence in Docs/release-checklist.md 'v0.1.0 release commit'>"`. No attribution line. Expected: prints the PR URL.

- [ ] **Step 2: Wait for the checks**

Run: `gh pr checks <n> --watch`
Expected: `roadmap`, `rust`, `ui`, `tauri-build`, `cargo-deny`, `workflows`, the `release.yml` dry-run jobs (`build (windows)`, `build (macos-arm64)`, `build (macos-x64)`, `build (linux)`; `publish` skipped by design) and both CodeQL results pass. Red check or a CodeQL "new alerts" result: stop and report (stop rule).

- [ ] **Step 3: Check the PR state, then merge with a merge commit**

Run: `gh pr view <n> --json mergeable,mergeStateStatus,baseRefName` (expected `MERGEABLE`, base `main`, state not `BEHIND`/`BLOCKED`). Then `gh pr merge <n> --merge` (no `--squash`, no `--rebase`, no `--delete-branch`). Expected: `gh pr view <n> --json state,mergeCommit` shows `MERGED` and a merge commit.

- [ ] **Step 4: Verify `main`**

Run: `git fetch origin && git show --stat origin/main | head -20` and `git show origin/main:Cargo.toml | grep -m1 '^version'`
Expected: `origin/main` is a merge commit with two parents; its `Cargo.toml` says `version = "0.1.0"`.

### Task 3: Create the release and verify the assets

**Files:** a notes file in the scratchpad directory (not in the repo).

**Interfaces:**
- Consumes: `origin/main` from Task 2 with the `[0.1.0]` CHANGELOG section.
- Produces: GitHub release `v0.1.0` (tag on `main`) with the assets; the `release.yml` run id.

- [ ] **Step 1: Extract the release notes**

Write the CHANGELOG section of `0.1.0` (the lines after the `## [0.1.0]` heading up to the next `## [`) into `$SCRATCH/notes-v0.1.0.md` (the session scratchpad directory). Expected: the file is non-empty and starts with the milestone line from Task 1 Step 4.

- [ ] **Step 2: Create the release**

Run: `gh release create v0.1.0 --target main --title "v0.1.0" --notes-file "$SCRATCH/notes-v0.1.0.md"`
Expected: prints the release URL; `git ls-remote --tags origin v0.1.0` lists the tag; `gh run list --workflow release.yml --event release --limit 1` shows a run for it.

- [ ] **Step 3: Watch the release run**

Run: `gh run watch <run-id> --exit-status`
Expected: jobs `build (windows)`, `build (macos-arm64)`, `build (macos-x64)`, `build (linux)` and `publish` succeed. A failed job: stop and report (stop rule); do not delete the release or tag. Re-attaching with `gh workflow run release.yml --ref dev -f tag=v0.1.0` needs the owner's decision.

- [ ] **Step 4: Verify the attached files**

Download into a new, empty directory under the scratchpad (`gh release download v0.1.0 --dir "$SCRATCH/dl-v0.1.0"`), then run:

```bash
(cd "$SCRATCH/dl-v0.1.0" && sha256sum -c SHA256SUMS)
bash tools/verify-installers.sh 0.1.0 "$SCRATCH/dl-v0.1.0"   # from the repo root
gh release view v0.1.0 --json isDraft,isPrerelease,tagName,targetCommitish
```

Expected: `sha256sum -c` reports `OK` for all five files (`fernjo_0.1.0_x64-setup.exe`, `fernjo_0.1.0_aarch64.dmg`, `fernjo_0.1.0_x64.dmg`, `fernjo_0.1.0_amd64.deb`, `fernjo_0.1.0_amd64.AppImage`); `verify-installers.sh` exits 0; the release is not a draft, not a pre-release, tag `v0.1.0`, target `main`.

**Interfaces:**
