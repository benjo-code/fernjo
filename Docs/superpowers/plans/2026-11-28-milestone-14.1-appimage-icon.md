# M14.1 AppImage Icon Note Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The AppImage's application menu dialog and the README say that the start menu and dock icon may appear only after the next log-in.

**Architecture:** The dialog text of `src-tauri/src/app_menu.rs` moves into a pure function that is tested on every OS; the Linux-only `offer` calls it. What fernjo writes to disk does not change.

**Tech Stack:** Rust (Tauri 2 shell crate `fernjo-app`), Markdown, `Docs/roadmap.json`.

**Spec:** `Docs/superpowers/specs/2026-11-28-m14-1-appimage-icon-design.md`

## Global Constraints

- The text of `fernjo.desktop` stays byte-identical to v0.4.0, so nobody who chose "Add" is asked again.
- No external programs, no cache refresh, no extra icon sizes; when and where fernjo writes does not change.
- No document claims that the cause is a cache. What is known: entry and icon were correct, the running Plasma session did not pick the icon up, a new log-in showed it.
- No user name or home path of the owner's machine in any committed file (public repo). Facts to record: KDE Plasma 6.8.3, Wayland, `XDG_DATA_HOME` unset.
- Native cargo builds are blocked on the development machine. Build, test and clippy run in the container; `cargo fmt` and `cargo deny` run natively. Container command, with `<args>` from the step (Bash tool):

  ```bash
  MSYS_NO_PATHCONV=1 docker run --rm -v "d:/VS-Code/fernjo:/src" -v fernjo-target:/target -v fernjo-cargo:/opt/cargo/registry -v fernjo-rustup:/opt/rustup fernjo-dev bash -c "cd /src && export CARGO_TARGET_DIR=/target CARGO_HOME=/opt/cargo && cargo <args>"
  ```

- Roadmap edits go into `Docs/roadmap.json`, followed by `dotnet run tools/roadmap.cs -- generate`; both files are committed together.
- Branch `feature/m14-1-appimage-icon`; stage files one by one; check `git show --stat HEAD` after each commit; no attribution lines.

## Review Focus

- An AppImage path or data folder with spaces, `%`, quotes or braces: the dialog shows it as it is on disk, not in `Exec` quoting (test in Task 1).
- Someone who chose "Add" with v0.4.0 starts the new version: no dialog (test in Task 1).
- Someone who moved the AppImage is asked again and sees the note (existing test `it_offers_only_for_an_appimage_that_has_no_matching_entry_and_no_never`).
- Someone who never sees the dialog again (current entry, or "Never") learns it only from the README (Task 2).
- A desktop where the icon appears at once (GNOME is not checked): the wording says "may", not "will" (exact-text test in Task 1).

- [ ] **Step 2: Write the three tests** in `app_menu::tests`.

```rust
#[test]
fn the_dialog_says_when_the_icon_may_appear_and_has_no_gaps() {
    let text = offer_message(Path::new("/home/u/.local/share"), APP);
    assert_eq!(
        text,
        format!(
            "fernjo runs as an AppImage, so your desktop has no application menu entry for it \
             and shows a placeholder icon in the title bar.\n\n\
             Add fernjo to your application menu? This writes two small files below \
             /home/u/.local/share and points the entry at\n{APP}\n\n\
             The icon may appear in the start menu and dock only after you log out and in \
             again.\n\n\
             If you want to move the AppImage first, choose \"Not now\"; the question comes \
             back at the next start."
        )
    );
    assert!(!text.contains("  "), "{text:?}");
}

#[test]
fn the_dialog_names_the_folder_and_the_appimage_as_they_are() {
    let app = "/h/a b/100% \"{x}\".AppImage";
    let text = offer_message(Path::new("/h/a b/share"), app);
    assert!(text.contains(" below /h/a b/share and "), "{text:?}");
    assert!(text.contains(&format!("\n{app}\n")), "{text:?}");
}

#[test]
fn an_entry_written_by_v0_4_0_is_not_asked_about_again() {
    let dir = tempfile::tempdir().unwrap();
    let (entry, _) = entry_paths(dir.path());
    std::fs::create_dir_all(entry.parent().unwrap()).unwrap();
    // a literal on purpose, not `desktop_entry`: this is the text v0.4.0 put on disk
    let written = format!(
        "[Desktop Entry]\nType=Application\nName=fernjo\nComment=SSH connection manager with a \
         connection tree and tabbed sessions.\nExec=\"{APP}\"\nIcon=fernjo\nStartupWMClass=fernjo\n\
         Categories=Development;\nTerminal=false\n"
    );
    std::fs::write(&entry, written).unwrap();
    assert!(!should_offer(Some(APP), dir.path(), false));
}
```
