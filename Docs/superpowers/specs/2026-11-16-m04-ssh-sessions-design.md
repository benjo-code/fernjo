# fernjo – Milestone 4 design: SSH sessions in tabs

**Status:** approved by the owner on 2026-11-16 (including the builder calls) · **Date:** 2026-11-16 · **Parent spec:** [2026-11-15-fernjo-design.md](2026-11-15-fernjo-design.md) (§3, §4, §5.3, §6) · **Visual language:** `DESIGN.md` · **Roadmap:** M4

This document records the decisions for M4 only. Intent, goals, non-goals and anti-goals are those of the parent spec. Decisions the owner made in conversation are marked *(owner)*; everything else is the builder's call with its reason.

## 1. Intent

After M4 the owner double-clicks an SSH connection and gets a terminal in a tab: authenticated with the agent, the stored key or the stored password (or asked), against a host key that fernjo has verified, usable for a full working day with `vim`, `htop` and ten tabs open. M4 is the first milestone that connects anywhere; M5 (import) and M6 (packaging) build on it.

## 2. Scope

**In:** the `fernjo-ssh` crate; the session manager and session commands in `src-tauri`; the tab strip, the terminal view and the inline prompts (host key, host key changed, keyboard-interactive, password, username, key passphrase, "needs vault"); the connect actions and lamps in the tree; terminal settings (font family, font size, scrollback); app shortcuts and their documentation in the README; the SSH integration tests in CI.

**Out:** RDP (M7; opening an RDP connection shows a notice "RDP sessions are not available yet"); SFTP, port forwarding, jump hosts, local shell tabs, split panes, detached tabs, quick connect and Pageant (all backlog); key-file paths (keys live in the vault; PuTTY `.ppk` is not read); restoring tabs after a restart; SSH legacy algorithms (`ssh-rsa` with SHA-1, DSA, 3DES); the full settings dialog (M6).

**Anti-goals:** a password, key or passphrase in a log, an event payload, `Debug` output, a response or webview storage (the session commands join the no-secret test); a host key accepted without the user's decision; a silent fallback after a host key mismatch; the UI freezing or Ctrl+C stalling while a command floods the terminal; app shortcuts that take keys the terminal needs.

## 3. Approaches

| Question | Chosen | Rejected |
|---|---|---|
| RSA keys *(owner: accepted the recommendation)* | **Support them.** Keep russh's `rsa` feature and add a `deny.toml` ignore for `RUSTSEC-2023-0071` (Marvin timing attack) with the reason and a removal condition. russh currently pins `rsa 0.10.0-rc.18` through `ssh-key 0.7.0-rc.*`, which the advisory flags; the fixed `rsa 0.10.0` exists but cannot be selected from here. Remove the ignore once russh depends on it. | Ed25519 and ECDSA only (many existing `~/.ssh` keys and older servers use RSA). |
| Crypto backend of russh | **`ring`** (`default-features = false`, features `flate2`, `ring`, `rsa`). It built on Windows in a throwaway crate with no extra toolchain, and licences pass the project allow-list. | The default `aws-lc-rs` (needs a C toolchain on every platform and in the release workflow, more to go wrong in M6). The first task re-checks the build on Windows and in CI before the choice is final. |
| How a session talks to the UI | **One Tauri channel per session** carrying typed events: `state` and `prompt` as JSON, terminal output as raw binary on the same channel. Input, resize, close, prompt answers and acknowledgements are commands. | An app-wide event stream for state next to a data channel (two ordering problems, every tab sees every event); base64 output inside JSON (about 33% overhead and an extra encode and decode on the hot path). |
| Where interactive prompts live | **In `fernjo-ssh` as an `Interaction` trait** (async methods returning the user's decision). `src-tauri` implements it by sending a `prompt` event and waiting on a one-shot that `answer_prompt` resolves. | Prompts implemented in `src-tauri` only (the host key and auth tests would need the UI). |
| Host key and integration tests in CI | **A step in the existing `rust` job** starts the OpenSSH container; `cargo test --workspace` then runs the integration tests against it. No new job, so the required status checks of `main` and `dev` do not change. | A separate `ssh-integration` job (clearer, but it would have to be added to the branch protection, which is a GitHub settings change that only happens on the owner's instruction). |

## 4. `fernjo-ssh` crate

No dependency on Tauri, `fernjo-core` or `fernjo-vault`; secrets arrive as `secrecy::SecretString`. Created in this milestone. Dependencies (`russh`, `ssh-key` as pulled by russh, `tokio`) and their versions go to `Docs/DECISIONS.md` when chosen; `cargo deny check` must stay green with the one new, reasoned ignore above.

- **Shape (not signatures):** `connect(params, interaction)` returns a `Session`; `ConnectParams` holds host, port, username (optional), keepalive seconds, the optional credential (`Password` or `PrivateKey { key, passphrase }`), the `known_hosts` path and the initial window size. A `Session` has `write(bytes)`, `resize(cols, rows)`, `close()` and an event receiver yielding output chunks and the end of the session with a reason. Everything is async on tokio.
- **PTY:** one session channel, `xterm-256color`, window size from the UI, then a login shell. Resize sends a window-change request.
- **Keepalive:** the inherited `keepaliveSecs` (default 30, 0 = off) becomes russh's keepalive interval; three unanswered keepalives end the session as "connection lost". Connect timeout 15 s for TCP and handshake *(builder's call)*.
- **Authentication, in OpenSSH order**, skipping every method the server does not offer or that is not available: (1) **agent**: every identity of the OpenSSH agent (`SSH_AUTH_SOCK` Unix socket on macOS and Linux, the `\\.\pipe\openssh-ssh-agent` named pipe on Windows; no agent running means skipped); (2) **key from the credential**, asking `Interaction::key_passphrase` when the key is encrypted and the entry stores no passphrase; (3) **password from the credential**; (4) **keyboard-interactive**, every round shown through `Interaction::keyboard_interactive` (name, instructions, prompts with the echo flag), enough for 2FA codes; (5) **ask for the password** through `Interaction::password`, at most three attempts like OpenSSH. A username that is neither set on the connection (or inherited) nor stored in the entry is asked through `Interaction::username`. The agent attempt count is capped so a large agent cannot trip the server's `MaxAuthTries` before the credential is tried *(builder's call: try at most five agent identities, preferring the one whose public key matches the credential if there is one)*. **Attempt budget** *(builder's call, from the review)*: the pure auth-order function also counts attempts and caps the total at 6 (a typical `MaxAuthTries`) before the final password prompts; the agent gets at most the remainder after reserving one attempt each for the credential key, the credential password and keyboard-interactive, and typed password retries count too. Supported user key types: Ed25519, ECDSA, RSA (SHA-2 signatures only).
- **Host keys:** `known_hosts` in the data folder, OpenSSH format (`host` or `[host]:port` for ports other than 22, written in clear, not hashed; hashed entries written by other tools are read and matched). A connection to an unknown host calls `Interaction::host_key` with host, port, key type and the OpenSSH-style `SHA256:` fingerprint and gets `TrustOnce`, `TrustAlways` (writes the line) or `Reject`. A stored key of the same type that differs calls `Interaction::host_key_changed` with the old and new fingerprints and gets `Replace` (rewrites the line, then continues) or `Reject`; nothing is sent to the server before the decision. If the host has stored keys, the offered host key algorithms are limited to their types, so a server that merely adds another algorithm is not mistaken for an attack. The file is written atomically like the other data files and stays readable by `ssh-keygen -F`. Because it lives in the data folder it is synced with the connections *(builder's call; it is what the parent spec says, and a host verified on one device then needs no second prompt)*.
- **Errors:** a typed error with a stable `code` (`connect_failed`, `timeout`, `host_key_rejected`, `host_key_changed_rejected`, `auth_failed`, `connection_lost`, `closed`, …) and a message fit for display; no message contains a secret.

## 5. Tauri layer

- **Session manager** in `AppState`: sessions by id, each a tokio task owning its `Session`. A node can have several sessions. Closing the app drops them all.
- **Commands (names the builder may adjust):** `open_session(node_id, channel, cols, rows)` returns the session id and resolves everything in Rust (effective host, port, username, keepalive, credential reference, then `Vault::reveal` when the vault is unlocked); `session_input(id, bytes)`; `session_resize(id, cols, rows)`; `session_ack(id, bytes)`; `close_session(id)`; `reconnect_session(id)`; `answer_prompt(id, prompt_id, answer)`; `resume_session(id, skip_credential)` (after an inline vault unlock, or with `skip_credential` when the user cancels the prompt); `open_external_url(url)` for web links (only `http` and `https`; called through `tauri-plugin-opener`'s Rust API so no JS capability is added, `capabilities/default.json` stays `core:default`); `get_terminal_settings` and `set_terminal_settings`. Each new `#[tauri::command]` follows the checklist in `CLAUDE.md` (wrapper, `table()` entry or `APP_HANDLE_EXEMPT` with a reason, `generate_handler!`, `sources`).
- **Credential resolution:** the connection's own or inherited username wins, the entry's username is the fallback (M3 decision). A locked vault with a credential reference gives the tab the state "needs vault"; the UI shows the inline unlock prompt, calls the existing `vault_unlock`, then `resume_session`; Cancel continues without the credential (agent, keyboard-interactive and password prompt remain). A dangling reference ("Missing credential") and an unusable vault (`VaultState::Unusable`) behave like no credential, and the tab says so in its status text *(builder's call, from the review)*.
- **Flow control:** output is batched (about 16 ms or 32 KiB, one SSH packet) before it crosses IPC. The UI acknowledges the bytes xterm.js has finished writing (`session_ack`); when more than a high-water mark of bytes (128 KiB, low-water 32 KiB) is unacknowledged, the session task stops reading from the SSH channel until acknowledgements bring it under the low-water mark. The SSH layer bounds the rest of the pipe too (window 512 KiB, 4 buffered packets, an event queue of 4), because everything ahead of the echo of Ctrl+C has to drain through xterm's parser first; the numbers are tuned against the requirement below and recorded in `Docs/DECISIONS.md` ("M4 flow control numbers"). Without this a `cat` of a large file buffers unboundedly in the webview and Ctrl+C reacts late. **Requirement (measurable):** after `yes` has run for 5 s, Ctrl+C returns the prompt within 1 s.
- **What crosses IPC:** session state, prompt descriptions (host, fingerprints, prompt texts), output bytes. Typed answers (passwords, 2FA codes, passphrases) travel UI → Rust only and are zeroised after use. No response or event has a secret field.
- **Terminal settings** live in `settings.json` as an optional `terminal` object (`fontFamily`, `fontSize`, `scrollback`; defaults: the `--font-mono` stack, 13, 10000; bounds 8..32 and 1000..100000). `schemaVersion` stays 1: the fields are additive and an older build that rewrites the file only loses the font preferences *(builder's call; unlike `connections.json`, `settings.json` is per machine and holds nothing that cannot be re-entered)*. While `FERNJO_DATA_DIR` is set the file is neither read nor written (existing rule): the settings then apply for the running session only and the dialog says so.

## 6. UI

- **Tab strip and area** (`DESIGN.md` "Tabs"): the main area shows the tab strip (36 px) over the session area; with no tab the empty hint stays, the vault manager remains a view that replaces the session area while open (a running terminal keeps running behind it).
- **Opening:** double-click or Enter on a connection, and "Connect" in the context menu, open or focus the connection's tab; "Open another session" opens a second tab ("name (2)"). An RDP connection shows the notice above. Tree rows show the lamp (`DESIGN.md` "Lamp column"): the strongest state of the node's sessions (connecting, live, dropped), none when it has no tab.
- **Tab states:** connecting (pulsing ring, "Connecting…"), "Needs vault", connected (filled dot), disconnected (struck ring, reason as caption, yellow **Reconnect** on every dropped tab). Reconnect starts a fresh remote session in the same tab and keeps the terminal buffer, with a dim separator line written into it *(builder's call: the scrollback of a dropped session is worth keeping)*. Tabs reorder by pointer drag (same pointer-event approach as the tree, no HTML5 drag and drop) and close with the × button or the shortcut; closing a **connected** tab asks for confirmation in the existing confirm dialog (Cancel has focus), closing a dropped tab does not *(builder's call)*.
- **Inline prompts** in the session area of the tab that needs them, in the layout of the existing inline unlock prompt (420 px column, 88 px from the top, other tabs keep running): host key (trust once, trust always, cancel), **host key changed** (a blocking warning that names both fingerprints; the default focus is Cancel; "Replace key and connect" is an outlined danger action, never the yellow key), keyboard-interactive (one field per prompt, masked unless the server says echo), password, username, key passphrase, needs vault. The yellow key is the single primary action of each prompt (One Key Rule); `DESIGN.md` gets a short "Session prompts" section describing the additions and uses only existing tokens.
- **Terminal:** xterm.js (`@xterm/xterm` with the fit, WebGL, search and web-links addons, versions pinned and recorded in `Docs/DECISIONS.md`). Theme from the `--term-*` tokens (re-read when the theme changes), `minimumContrastRatio` from `--terminal-min-contrast`, cursor and selection as in `DESIGN.md`. The WebGL renderer is used only for the visible tab (one context at a time, created on show and disposed on hide, because browsers cap WebGL contexts) and falls back to the DOM renderer if WebGL is missing or the context is lost, which happens on WebKitGTK. Hidden tabs keep their xterm instance and keep receiving output. Fit follows the tab area and sends `session_resize`. A search bar (Ctrl+Shift+F) and clickable URLs (through `open_external_url`).
- **Copy and paste:** copy with the selection through Ctrl+Shift+C (Cmd+C on macOS) and the terminal context menu; paste with Ctrl+Shift+V (Cmd+V) and the menu. Ctrl+C and Ctrl+V always reach the program. Bracketed paste is left to xterm.js. The exact clipboard path (browser clipboard API versus a Rust-side clipboard command) is decided by a short check on Windows in the first terminal task; the choice and the reason go to `Docs/DECISIONS.md`.
- **Shortcuts:** inside a focused terminal only chords with Ctrl+Shift (Cmd on macOS) and Ctrl+Tab are app shortcuts; plain Ctrl+letter, Alt+letter and Escape always go to the program. The set: next and previous tab (Ctrl+Tab, Ctrl+Shift+Tab), close tab (Ctrl+Shift+W, Cmd+W), focus the filter (Ctrl+Shift+K, Cmd+K), terminal search (Ctrl+Shift+F, Cmd+F), copy and paste as above. A pure function maps a key event and platform to an app action or "terminal" and is unit-tested; the set is documented in the README *(the exact chords are the builder's call within the rule; the list above is the proposal)*.
- **Terminal settings:** the existing gear dialog gains a "Terminal" section (font family, font size, scrollback), applied live to open terminals. M6 folds the dialog into the full settings dialog. This overlaps the M6 task "terminal font and size, scrollback" and is recorded in the roadmap as a scope change.

## 7. Verification (feeds the roadmap acceptance criteria)

- **`fernjo-ssh` unit tests:** `known_hosts` parse, write, match (default and non-default port, hashed entries, several keys per host), mismatch detection, fingerprint format against `ssh-keygen -lf`-style known values; authentication order as a pure function over (server methods, available credentials); error codes carry no secret.
- **Integration tests against an OpenSSH server container** (image pinned by digest; started by a `rust` job step in CI, by a script under `tools/` locally): password, key (Ed25519 and RSA), agent (an `ssh-agent` started in the job), keyboard-interactive (the server's PAM password prompt), host key unknown then trusted then known, **host key mismatch** (a `known_hosts` line with a different key: the session never authenticates), wrong password ends in `auth_failed` after three prompts, resize reaches the server (`stty size`), keepalive off and on. Test keys and passwords are generated per run, never committed. When the server address variable is unset, the tests skip with a message locally and **fail** when `CI` is set, so they can never be skipped silently in CI.
- **No-secret test:** the session commands run in the table of `no_response_contains_a_secret` with sentinel secrets in the vault; no response, event, error or `Debug` output contains one.
- **UI tests (Vitest):** tab store (open or focus, second session, reorder, close, states, reconnect), prompt components for each prompt kind including the host-key-changed default focus, the shortcut mapping function, lamp state for a node with several sessions, terminal wrapper behaviour with xterm mocked (fit sends resize, acknowledgements follow writes, WebGL fallback).
- **Manual (Windows, real app over the DevTools protocol, plus a real host):** each auth method against a real host; `vim` and `htop` render and resize correctly; ten tabs open at once with one `htop` and one `yes` running; Ctrl+C after `yes` within 1 s; the host key prompt and the mismatch warning; copy and paste; a dropped connection (network cable or `kill` of the server session) shows Reconnect. macOS and Linux (including the WebGL fallback on WebKitGTK and the Secret Service path) go to "Open manual checks (owner)".
- **Gate:** the commands in `CLAUDE.md` (build, tests, lint, `cargo deny check`, roadmap check) green.
