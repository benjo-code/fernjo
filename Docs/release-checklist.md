## v0.1.0 security review

Review date: 2026-11-18 (Windows 11; CI dry-run installers of run `44205574554`, PR #10). The checks of Steps 1-4 ran on `target/release/fernjo.exe` built from commit `1bc2762` (built after the last commit that touched `src-tauri`, `crates` or `ui`). The fix commits of this review (`64aa818`, `6648cff`, `5791506`) and the later import fixes (`36c3be0`, `de2a615`, `c809677`) post-date that binary; the real-app checks were not repeated on a rebuild, so they say nothing about those changes (the code fixes have their own tests). Every check below records its command, its result and the date. Real-app checks ran with a scratch `FERNJO_DATA_DIR`; the owner's real data folder was not read, printed or modified, and "Unlock automatically on this device" was never ticked.

#### Independent review (Step 9)

Scope: three reviewers (opus, fresh, given the code and not these conclusions) read `crates/fernjo-vault`, `crates/fernjo-ssh` (host-key path) and `crates/fernjo-import` with `src-tauri/src/import_commands.rs`, read-only, probes in a scratch folder; their reports are `security-review-vault.md`, `security-review-ssh.md` and `security-review-import.md` in `.superpowers/sdd/2026-11-17-milestone-06-packaging-release-readiness/`. Findings below were checked against the code by reading (vault M1, M3 and ssh L1 re-read for this table); the reviewers' timings and probe results are theirs and were not rerun here. The reviewers' two zero-High results: no authentication bypass, no nonce reuse, no header downgrade, no panic on malformed input and no secret in `Debug`/logs in the vault; no path where a credential is sent before the host key is accepted, and no path where an error, timeout or closed UI yields "trust" in the SSH host-key code. What each found sound is in the "Checked and found sound" sections of the reports (vault: AEAD/KDF use, nonces, AAD binding, key hierarchy, parsing, KDF bounds, secret types, keychain, save guard, atomic write; ssh: signature verified before the handler runs, authentication strictly after the handshake, every error path rejects, UI prompts fail closed, hostile `known_hosts` forms never match, channel and terminal surface; import: DTD refused, nesting and node caps, PBKDF2 work budget, no unchecked slice or cast, backup container authenticated and bounded, restore rollback, no path from the webview, no `@html`). Their severities are the reviewers' unless a ruling is noted. `/security-review` on the full milestone diff (`git diff dev...HEAD`) is still to be run by the controller: rows from it go below as 21 onwards.
