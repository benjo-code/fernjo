# Changelog

All notable changes to this project are documented here.

Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning according to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Every release entry names the milestones it contains.

## [Unreleased]

Daily-use features: milestone M10.

### Added

- Quick connect (M10): type `user@host`, `user@host:port`, `ssh://user@host` or `rdp://[user@]host[:port]` into the field under the filter (Ctrl+Shift+N, Cmd+N on macOS) and press Enter to open a session without saving a connection. Nothing is written to `connections.json` or the vault; sign-in uses the agent and the prompts in the tab. A quick remote desktop has its clipboard switched off. Reconnect works for these tabs.
- Reopen tabs on start (M10): the tabs of the last run (saved connections and quick targets, the order and the active tab) come back after a restart as disconnected tabs ("Restored from your last session. Not connected."); nothing connects until you press Reconnect on a tab or "Reconnect all" in the tab strip (three at a time; the vault is asked for once when a tab needs it). The list is kept per device in the device folder and holds only targets, never a credential. Switch it off in Settings, "Tabs".
- Vault auto-lock (M10): Settings, "Vault", has an idle time in minutes (1 to 1440, empty is off, off by default). After that long without keyboard, mouse or wheel input in fernjo (time the computer was asleep counts) the vault locks, also while a terminal or remote desktop has the focus; connected sessions keep running.
- Pageant on Windows (M10): when the OpenSSH agent is not running or holds no keys, fernjo uses Pageant. If both hold keys only the OpenSSH agent is used.
- Quit confirmation with Cmd+Q on macOS (M10): quitting with a connected session now asks "Close fernjo?" like closing the window does.
- Native paste (M10): the terminal's context-menu Paste reads the clipboard through the app instead of the web view, so it no longer waits for a permission prompt on Windows. The clipboard library's licence (BSL-1.0) is now allowed in `deny.toml` and listed in the third-party notices. Known exposure: the command can be called by any script in the web view, which only runs fernjo's own bundle (`Docs/DECISIONS.md`, "M10 native clipboard: BSL-1.0 allowed").
- Restoring a backup now names what is replaced (connections and credentials; open sessions are closed) and what is kept (the vault password, known hosts, settings and sync setup). With sync on, a restore is still pushed to your other devices at the next run, and the confirmation now says so (M11).
- Remote desktop tabs that share the clipboard show a small clipboard mark; its tooltip reads "Clipboard shared with <host>" (M11). The clipboard stays on by default for saved connections; switch it off per connection or folder.
- Multi-device sync (M9): your connection tree and your vault entries can follow you between devices without copying files and without a file-sync tool. You run one small program, `fernjo-hub`, on a machine that is always on (rootless Podman on an Ubuntu or Debian VM, behind the Caddy you already run with `tls internal`; the guide is `Docs/hub.md`), and every device talks to it over HTTPS. Reaching the hub from outside the home network is not built (the address is configurable, but only the LAN case was designed). Set it up in Settings, Sync: hub address, the hub secret that `fernjo-hub init` prints once, optionally Caddy's root certificate, and a device name. "Show pairing code" gives one string that you paste on the next device under "Join with a pairing code"; joining replaces that device's connections and vault with the shared ones, after a confirmation that counts what is lost.
  - The hub stores only encrypted snapshots: the snapshot is encrypted on the device with a key the hub never receives (XChaCha20-Poly1305, HKDF-SHA256), and the vault inside is still protected by your master password. The hub sees sizes, times and a counter, nothing readable, and cannot forge a head that devices accept. The hub secret and the sync key live in the OS keychain; sync cannot be set up without one. A device refuses a hub that shows an older state than it has seen (for example a restored VM) and offers "Re-seed hub from this device".
  - It works offline-first: saving never waits for the hub. A device syncs after start, every five minutes, when the window gets focus, a few seconds after you change something, with "Sync now", and tries one last push when you close the window. An unreachable hub is the quiet state "Offline, N changes waiting" in the sidebar footer, not an error.
  - Merging is three-way, per connection, folder and vault entry. Different edits are both kept; an edit beats a delete; when both sides changed the same field differently the other device's value stays and yours becomes a new item named "<name> (conflict <device> <date>)" next to it, and a notice says so. Both sides moving a node to different folders keeps the hub's place; a move that would make a loop or go deeper than 60 levels is undone. If both sides changed the vault, merging needs it unlocked and sync waits ("Sync paused: unlock the vault") until it is; if only one side changed the vault file it is taken as it is, even while locked. Two vaults that were created independently are not merged: the run stops with a notice and nothing is lost on either side (you resolve it by hand, and the tree does not sync until you do).
  - What stays per device and is not synced: known SSH host keys and the host-key confirmations, the RDP certificate pins, terminal and theme settings, window layout, the vault's rollback marks and the keychain auto-unlock item. Every host therefore still asks once on each device. Do not combine fernjo's sync with a file-sync tool on the same data folder.
  - The format is written down in `Docs/sync-format.md` (envelope, snapshot, hub API, pairing code, merge rules), so a compatible client or hub needs no fernjo source.
  - Limits that matter: edits made away from the network reach the hub only while fernjo is running on that device inside the network; the hub is one machine and keeps the newest snapshot plus ten older ones as files (no screen restores them; copy one over `head.env` yourself); a lost or stolen device is locked out with `fernjo-hub rotate-secret` and the other devices need the new secret ("Edit hub secret"); the sync key itself is never rotated in this version (leave sync everywhere and set it up again to change it); if every device is lost the hub's data cannot be read, so keep an encrypted backup. A hub that shows different devices different histories is not detected.
  - Known limits: changing the data folder to a different, already filled folder while sync is on makes the other folder's connections look like deletions and the next run would push them, so leave sync first and join again afterwards; the names of vault entries in a merge notice stay in the notice bar after the vault is locked until you dismiss it; a master password changed on one device while another device edited the vault is replaced by the other device's password and a notice says so (change it again).
  - **Verified on real hardware, except Linux.** The owner ran a Windows 11 PC and a macOS laptop against a hub in rootless Podman 5.7.0 behind Caddy `tls internal` on a separate VM (create, edit, delete versus edit, conflict copy, vault entry, offline then online, hub and Caddy restart, hub restored from an older snapshot and re-seeded, hub secret rotation, the OS keychain items on both systems). That run found two defects, fixed before release: the Quadlet unit used `Init=` (the key is `RunInit=`), and the notice for an item deleted on one device and changed on another said "changed here" also on the device that had deleted it. Not run: the Linux Secret Service keychain item and a Linux device.
- The Reload bar (M7) now also appears when a vault credential delete or a restore from a backup finds that `connections.json` changed on disk, in addition to the plain error text. The file in question can be `vault.fernjo` (a restore saves the vault first), while the bar still names `connections.json`.
- Opening the vault now removes leftover `vault.fernjo.<hex>.tmp` files of an interrupted save that are more than a day old; younger ones, symbolic links and other names are left alone.
- Build provenance for the installers (M11): from v0.3.0 on every installer of a release carries a GitHub build attestation. `gh attestation verify <installer file> --repo benjo-code/fernjo --signer-workflow benjo-code/fernjo/.github/workflows/release.yml` shows that the file was built by fernjo's release workflow in this repository (`SHA256SUMS` only shows that a download is intact). Earlier releases have none.

### Changed

- RDP (M11): fernjo now requires Network Level Authentication (NLA): the password is only ever sent inside NLA (CredSSP). A server that does not offer CredSSP (security layer set to "RDP" or "SSL" only, some xrdp setups, very old hosts) is refused with "the server does not offer Network Level Authentication (NLA)" before any certificate question or password prompt, and fernjo sends it nothing further, so such a server (or a machine in the path pretending to be one) never receives the password. A Windows host where NLA is merely not required still connects over CredSSP.

### Fixed

- RDP TLS (M11): fernjo checks the server certificate with its own verifier. It no longer needs the operating system's root certificates (a Linux machine without them got "the secure connection to the server failed" for every RDP host), and certificates signed with SHA-1, issued for another name or past their expiry date reach the certificate prompt as before (the pin decides trust). The TLS handshake signature is still always checked against the certificate's key. A host whose certificate the TLS library cannot use (for example an RSA key under 2048 bits, or an unknown extension marked critical) now fails with its own message, "the server certificate is not supported", before any prompt (see the known limit in the README).
- SSH (M11): closing the tab of a server that stopped reading now ends the connection within a few seconds; before, the connection and its background work stayed until fernjo quit. Such a frozen connection is still not detected by itself: the tab shows "connected" until you close it.
- SSH (M11): a sign-in question from the server (keyboard-interactive) now says which server asks ("The server <host> asks:"), shows the server's text in a marked block and says where the answer goes, so a server cannot make its question look like one of fernjo's own prompts (for example the vault password).
- SSH (M11): this device's confirmed host keys now outrank the synced `known_hosts`: their key types are offered first, and a key that differs from any key this device confirmed for the host (of any type, also when `known_hosts` no longer lists the host or lists a key of another type) shows the "host key has changed" warning with the confirmed fingerprints, instead of a first-contact or "added by another device" prompt. The latter now only appears for hosts this device has confirmed nothing for, and no longer lists earlier fingerprints.
- RDP (M11): a server can no longer make fernjo hold screen updates or pointer images without limit. A screen update sent in pieces may reach 8 MiB, or twice the size of the remote desktop when that is more, and a pointer must fit the 32 cache entries and 384 pixels per side that fernjo announces; a server that goes beyond ends the session with "The server sent a display update beyond the limits of this client."
- RDP (M11): text the remote desktop copies reaches your clipboard at most twice a second; when the remote side copies faster, only the latest text is taken.
- Sync (M11): when both devices changed the vault, a head that carries an older version of the vault than the last synced one is refused ("The hub shows an older state than this device has seen") instead of being merged; before, the credentials added since that version were dropped on every device and the old master password came back.
- Sync (M11): a `vault.fernjo` that something else put into the data folder while fernjo runs (an older copy, another vault's file) is no longer pushed to the other devices. The run, "Re-seed" and set-up stop with "The data changed on disk while syncing"; lock and unlock the vault to take such a file on. Set-up and re-seed also refuse a vault file that cannot be read.
- Sync (M11): release builds accept only `https://` hub addresses; plain `http://` to `127.0.0.1` or `[::1]` is refused (it was meant for tests only), so a hub on the same machine needs the TLS proxy too.
- SSH (M11): channels a server tries to open towards fernjo (forwarding, X11, agent, a second session) are refused; fernjo asks for none, and before they were accepted and kept.
- Host keys are written to `known_hosts` only after the SSH handshake succeeded (before, the decision was written inside the key check; the library already verified the signature first, so this is defence in depth). A failed handshake leaves the file unchanged.
- Reading JSON files no longer costs many times their size in memory (M11): a hostile connections export, backup, sync snapshot or a `connections.json` or `settings.json` with junk in it could make fernjo allocate gigabytes (a 32 MiB import file took 3 GiB, a `connections.json` at the 64 MiB limit about 6 GiB on every start, which can end the program). Reading now needs a small multiple of the file's size. A key that appears twice in one object of `connections.json`, `settings.json` or a sync state file now makes that file unreadable (the last one used to win; fernjo never writes such a file).
- The input a session can have waiting is capped at 8 MiB; beyond it the call is refused with "too much input is waiting; try again" instead of growing memory.
- App shortcuts (Ctrl+Shift+letter, Cmd+letter) work on non-Latin keyboard layouts, and Ctrl+Shift+W no longer closes a hidden tab while the vault view is open.
- The splitter's keyboard focus is a 1 px centred line and its hit area no longer covers the tree's scrollbar.
- The tree keeps 21 rows at the default window size instead of 23 (the quick connect field takes the room) so the properties panel stays reachable at 1280x800.
- Data files are never read or copied through a symbolic link at their own name (M11): a `known_hosts`, `settings.json` or other data file that is a symbolic link (a sync tool can plant one pointing at, for example, a private SSH key) is refused instead of being read and written back, together with its `.bak`, as a regular file in the synced folder. A FIFO or device at the name is refused without blocking, and `known_hosts` is read only up to 16 MiB. A single data file you linked on purpose (for example `known_hosts` to `~/.ssh/known_hosts`) now makes the connect or load fail with an error; link the whole data folder instead. Choosing a new data folder copies `connections.json` and the vault the same way (never through a link at the source name, never through a fixed temporary name in the new folder).
- Terminal paste (M11): pasted text can no longer end the shell's paste mode early and run as typed commands. fernjo removes the bracketed-paste markers and every control character except tab and line ends from text before it reaches the terminal (menu Paste and the keyboard paste); multi-line pastes keep their lines.
- RDP clipboard (M11): a remote desktop tab in the background no longer writes what its server copies to your clipboard. Only the remote desktop in front with the focus does; text copied meanwhile is written when you return to that tab.
- Hyperlinks a server prints in the terminal (OSC 8, for example from `ls --hyperlink`) now open in your browser through the same checks as plain links, and only for http and https; before, clicking one showed a browser confirmation with the server's text and opened nothing (M11).
- Quick connect (M11): `user:password@host` is refused with "type only the user name (no :password); fernjo asks for the password", so a typed password never lands in the tab title, the saved open tabs or the server's log as a user name.
- "Restart now" after a data folder change (M11) now asks "Restart fernjo?" while a session is connected, like closing the window, and gives sync its last push before restarting.
- The remote desktop tab's clipboard mark (M11) now always shows the clipboard setting the session really uses; it could disagree for a moment after a sync or an edit.
- Pasting against a clipboard that never answers (M11) no longer piles up background work that could stall sync, import and export; while one read hangs, further pastes fail at once.
- Vault auto-lock (M11): when the idle time had already run out while the computer slept, the first key press or mouse move after waking now locks the vault instead of restarting the idle clock.
- Locking the vault (M11) also drops an import or restore that was waiting with decrypted passwords (an mRemoteNG file with credentials, a backup with entries); pick and inspect it again after unlocking. Locking and the vault status no longer read the stored unlock key from the keychain.
- Import (M11): names, descriptions, hosts and domains from an mRemoteNG file lose control characters, and text from every import path (mRemoteNG, connections file, backup) loses right-to-left overrides and other direction characters that could display a name reversed. The RDP domain setting is cleaned the same way.
- Import (M11): closing or reloading the window while a picked file is being read no longer leaves the decrypted backup in memory.
- Data safety (M11): `connections.json` is compared with the exact bytes fernjo loaded, not with a second read, so a file replaced by a sync tool during loading is no longer overwritten without the "changed on disk" notice.

## [0.2.0] - 2026-11-22

RDP: milestone M8 (RDP sessions in tabs next to SSH, inheritable RDP settings, `connections.json` schema 3, mRemoteNG import of RDP display settings).

### Added

- RDP sessions (M8): an RDP connection in the tree opens as a tab next to the SSH sessions. It connects with TLS and network level authentication (user name, password and domain from the vault, or asked in the tab), shows the remote desktop on a canvas, takes keyboard and mouse input (the physical key counts, so the server's own keyboard layout applies), follows the size of the tab when the window or the sidebar changes (or keeps a fixed resolution and scales), shares text copy and paste both ways, and has an in-app full screen (Ctrl+Shift+F11 in and out; in a remote desktop only this and Ctrl+Tab belong to fernjo, every other key goes to the remote machine). The first connection to a server asks whether to trust its certificate (the fingerprint is remembered on this device; a changed certificate blocks and asks; self-signed certificates are accepted, but the server has to prove with the TLS handshake that it holds the certificate's private key, so replaying a public certificate does not pass; this check was added after the owner's run and has not been tried against a Windows host yet, only against a test server), and a session that ends keeps its tab with the reason and Reconnect. Display, clipboard and domain settings (resolution fit or fixed, colour depth, clipboard on or off, domain) are inheritable like the SSH settings; `connections.json` moves to schema version 3 (older files load unchanged). The mRemoteNG import now carries colour depth and resolution. Tried by the owner from Windows, macOS and Linux against Windows 11 hosts, with development builds (`pnpm tauri dev`); not tried against Windows Server, and an RDP session in an installed release build is not verified (the installers were built and smoke-tested on CI runners, which proves that the app starts, not an RDP session). The clipboard depends on what each web view allows. Known limits found by the release review and not fixed (see `Docs/roadmap.json`, backlog): a hostile RDP server can make fernjo buffer unbounded data on a virtual channel before the 1 MiB clipboard cap applies (switch the connection's clipboard off for hosts you do not trust), and the RDP clipboard is on by default and copies your local clipboard to the remote machine when the remote desktop gets the focus. RDP drive, printer and audio redirection, gateways and Kerberos are not supported.
- Linux AppImage: on start, fernjo offers to add itself to your application menu ("Add", "Never" or "Not now"), which is what the desktop needs to show the app icon instead of a placeholder in the title bar. It writes `fernjo.desktop` and the icon below `~/.local/share` only if you choose "Add", and asks again at the next start after "Not now" (so you can move the AppImage first) or when the AppImage has moved. Whether this fixes the title bar icon is not confirmed yet.

### Changed

- fernjo now also makes the RDP connections you open (M8); it still has no update check, telemetry or analytics.
- SSH RSA-key signing and RDP share a release candidate of the `rsa` crate (`0.10.0-rc.18`), because IronRDP's `picky` pins it; the advisory `RUSTSEC-2023-0071` (Marvin attack, not constant time) is ignored in `deny.toml` by owner decision of 2026-11-20 and is revisited at every IronRDP update. RDP itself does no RSA private-key work in a password client.

### Fixed

- The properties panel can now be dragged taller, not only smaller: once you set its height, the connection tree only has to keep 6 rows (before, it kept 23, which left no room to grow at the default size). Without a stored height the layout is unchanged, and a double-click on the bar still resets it.

## [0.1.1] - 2026-11-20

Polish and hardening: milestone M7 (no silent loss of synced data, quit confirmation, tabs that close on a deliberate shell exit, resizable panels, multi-select in the tree, a UI whose vault, import and settings can be found without a hint, and the Low findings of the M6 reviews settled).

### Added

- Data safety (M7): fernjo no longer overwrites a `connections.json` that a sync tool or another device changed while the app was running. The save is refused, a bar above the tree says so and offers **Reload**, which loads the other version (your edit that was refused is not applied; make it again after the reload). If the changed file cannot be read, the tree you see stays and the error is shown. It is a check before the write, not a lock, so a sync tool can still win a race of a few milliseconds.
- Quit confirmation (M7): closing the window while at least one session is connected asks "Close fernjo?" with "Close" and "Keep open"; with no connected session (or only connecting or disconnected tabs) the window closes at once. On macOS, Cmd+Q still quits without asking.
- Close on exit (M7): a tab closes by itself when the remote shell ends on purpose (`exit`, `logout` or Ctrl+D, when the shell reports exit status 0 after at least five seconds of connection). A non-zero exit status, a lost connection, a failed login or a session that ends right after it starts keeps the tab with Reconnect. Settings has a checkbox "Close the tab when the shell exits" (on by default).
- Resizable panels (M7): drag the right edge of the sidebar or the top edge of the properties panel, or focus the separator and use the arrow keys (Shift for bigger steps, Home and End for the limits); double-click resets. The sizes are remembered on this device, and the tree always keeps its rows.
- Multi-select in the connection tree (M7): Ctrl or Cmd+click toggles a row, Shift+click or Shift+arrow selects a range, and dragging a selected row moves the whole selection in one step. Deleting several asks first and says how many connections and folders go; the context menu on a selection offers Delete only, and the properties panel shows how many items are selected.
- Discoverability (M7, from a design review of the whole app, `Docs/design/m07-discoverability-review.md`):
  - The vault is named where you look for it: the sidebar chip reads "Vault: unlocked", "Vault: locked" or "Vault: none", the manager is titled "Vault", and the no-vault note is a slim one-line row with a "Create vault" button; a tab that waits for the vault now says "Unlock vault" (it said "Needs vault").
  - A connection's Credential row has "Create vault", "Unlock" or "Manage…" next to the value and a last entry "New credential…" in its dropdown; the row sits right under Username so it is visible without scrolling.
  - The sidebar footer buttons carry text ("Settings", "Import / Export") and the dialog is called "Import, export & backup".
  - An empty tree shows a numbered start list (add a connection, import from mRemoteNG, optionally create a vault); with connections the main area says "Double-click a connection (or press Enter) to open it."
  - Settings says what is applied live and what "Save terminal settings" stores, and lists the keyboard and mouse shortcuts for your platform; the context menu shows the key hints (Enter, F2, Del).
  - A dropped tab keeps its title and shows the reason ("The connection was lost.", "The remote shell ended (exit status 3).") in a bar above the terminal with Reconnect.
  - The host key prompt explains what each choice does.
- Security hardening (M7, from the Low findings of the M6 reviews, triaged in `Docs/DECISIONS.md`):
  - Vault: the Argon2 cost read from a vault file or backup header is bounded to at most four times the default per setting (memory, passes and lanes: about 16 times the default's work, roughly 40% below the old 1 GiB x 20 passes) and anything above is refused as unreadable, so a hostile synced file cannot make every unlock attempt take many seconds; `vault.fernjo` and `known_hosts` are written through a random temporary file name created with `create_new` (no fixed name that a planted symlink could redirect) and, on Unix, the directory is synced afterwards; changing the master password raises a weaker stored cost to the current default; the Windows keychain item is stored as `Local` (not roamed between machines) when it is newly written; an existing item switches the next time the key is stored (untick and tick "Unlock automatically on this device" in the vault manager).
  - Import: long and control characters in names, hosts and descriptions of JSON and backup imports are cleaned like mRemoteNG imports; text from a backup header is cut before it reaches the window; an export may not target the configuration folder, the device-local folder or a pending data folder; a reload of the page during a slow import no longer freezes the window; a notice appears when `settings.json` points at a data folder that contains the device-local folder.

### Changed

- The SSH agent's sign step has its own limit of 120 seconds (M7), so an agent that waits for a touch or a confirmation per signature (`ssh-add -c`) no longer runs into the 15 second connect timeout.
- The Settings dialog names the real reason when settings are not saved (M7): `FERNJO_DATA_DIR` is set, `settings.json` is unreadable or from a newer version, or the device has no settings folder. Before, it always blamed `FERNJO_DATA_DIR`.
- The Windows web view no longer runs its component updater (M7): about a minute after start it contacted `edge.microsoft.com` once while fernjo sat idle; `--disable-component-update` stops that (measured, see `Docs/DECISIONS.md`)
- Release binaries no longer embed the build machine's cargo registry paths (M7): the release workflow remaps the paths and fails when the built binary still contains one. The release workflow checks this on every release build; the dry run of pull request #16 passed that check on Windows, macOS (both architectures) and Linux.

### Fixed

- An oversize `connections.json` or `settings.json` (over 64 MiB) is refused as unreadable instead of being read whole (M7).
- A `known_hosts` line that lists several hosts (`a,b ssh-ed25519 ...`) no longer keeps the old key trusted for a host whose key you replace, and "trust always" for a host that presented a different key of the same type replaces the stored one (M7).
- A hostile keyboard-interactive prompt from a server is shortened (at most 16 prompts, long texts cut) before it is shown (M7).
- Linux (M7): the default window icon is now also applied explicitly after the window is created, as an attempt to remove the placeholder icon in the title bar under Wayland. Unconfirmed until it is looked at on a Linux desktop.

## [0.1.0] - 2026-11-18

First release, the "Daily SSH driver": milestones M0 to M6 (project foundation, design, connection tree, credential vault, SSH sessions in tabs, mRemoteNG import with export and backup, packaging and security fixes).

### Added

- Project foundation (M0): Rust workspace, Tauri 2 shell with an empty window, Svelte 5 frontend, CI on GitHub-hosted runners (build, tests, lint, `cargo deny`, CodeQL), dual MIT/Apache-2.0 licence.
- Visual design "Ulm, revised": light and dark theme that follows the system setting, bundled fonts (Hanken Grotesk, Red Hat Mono), design tokens for all upcoming UI (M1).
- New app icon (M1).
- Connection tree (M2): folders and SSH/RDP connections in a sidebar tree with filter, expand/collapse, keyboard navigation, rename, duplicate, delete with confirmation, context menu and drag and drop; the tree is saved to `connections.json` in the app's data folder (atomic write with a `.bak` backup).
- Inherited settings (M2): username, port and keepalive can be set on a folder and are inherited by everything below it; the properties panel shows "from <folder>" and an "Inherit" reset.
- Single instance (M2): starting fernjo a second time brings the running window to the front.
- Credential vault (M3): passwords and private keys (with optional passphrase) are stored in an encrypted vault file (`vault.fernjo`: Argon2id, XChaCha20-Poly1305, wrapped random data key; format in `Docs/vault-format.md`). Create it with a master password, lock and unlock it, change the master password, and manage entries in the vault manager (list, create, edit, explicit reveal that hides again after 10 seconds, delete with a usage warning). Optionally unlock automatically on this device through the OS keychain (Windows Credential Manager, macOS Keychain, Secret Service).
- Credential reference (M3): a connection or folder can reference a vault entry in the properties panel; the reference is inherited like username and port ("from <folder>"). `connections.json` stores only the entry's id (schema version 2; builds from before M3 refuse the file instead of dropping the reference).
- Data folder (M3): the data folder can be changed from the gear button in the sidebar; the data is copied to the chosen folder and the change applies after a restart. `FERNJO_DATA_DIR` still overrides it.
- Sync-conflict warning (M3): copies such as `connections.sync-conflict-…json` left by Syncthing, Nextcloud or Dropbox in the data folder are reported in a notice.
- Vault safety (M3): the vault refuses to overwrite a `vault.fernjo` that a sync tool or another device changed after it was unlocked ("Lock and unlock the vault to load the changes"); replacing a private key keeps its passphrase unless you tick "Remove stored passphrase"; unticking "Unlock automatically on this device" while unlocking turns it off; the lock note is compact until you ask for the password form; an unusable vault names `vault.fernjo.bak` for a manual restore. Changing the master password does not change older copies of the vault file (backups, sync history): they keep opening with the previous password.
- SSH sessions in tabs (M4): double-click a connection to open it as a terminal tab (xterm.js, WebGL renderer for the visible tab, search, clickable links, copy and paste). Tabs show connecting, connected and disconnected states with a lamp, can be reordered, closed (with a confirmation while connected), opened a second time as another session and reconnected after a dropped connection; the screen is kept.
- SSH sign-in (M4): SSH agent, then key (Ed25519, RSA, encrypted keys with passphrase), password, keyboard-interactive, then an inline prompt in the tab. A locked vault parks the tab until you unlock it.
- Host key verification (M4): fernjo's own OpenSSH-format `known_hosts` in the data folder; a first-contact fingerprint prompt (trust always or once) and a blocking warning when a stored key changes.
- Terminal settings (M4): font family, font size and scrollback in the Settings dialog (the gear in the sidebar), applied live and stored in `settings.json`.
- App shortcuts (M4): tab switching, close tab, filter, terminal search, copy and paste that leave the terminal's own keys alone; listed in the README.
- Import and backup (M5): import connections and passwords from mRemoteNG (confCons.xml, version 2.6); export connections as JSON; encrypted full backup and restore (formats in `Docs/backup-format.md`).
- Double-clicking a folder in the tree expands or collapses it (M4).
- Theme setting (M6): Settings has an Appearance section with System, Light and Dark; the choice is stored in `settings.json` and applied from a copy kept in the web view as soon as the page script runs, so a stored theme normally does not flash the other one at start (without that copy, on a first start, it follows the system theme until the settings have loaded).
- Installers (M6): the release workflow builds a Windows setup (`fernjo_<version>_x64-setup.exe`), macOS images for Apple Silicon and Intel (`_aarch64.dmg`, `_x64.dmg`) and a Linux `.deb` and AppImage (`_amd64`) on GitHub-hosted runners and attaches them to a published release. Each installer is smoke-tested on its runner first. The installers are not code-signed; README, section "Install", explains the Windows and macOS warnings.
- `SHA256SUMS` (M6): every release carries a checksum file for all installers.
- Third-party notices (M6): the licences of the bundled Rust crates, npm packages and the two fonts ship inside every installer (`THIRD-PARTY-NOTICES.md`).
- Per-user Windows install (M6): the setup installs under `%LOCALAPPDATA%\fernjo` without administrator rights; uninstalling keeps `%APPDATA%\fernjo`.
- Security hardening (M6, from the pre-release security review in `Docs/release-checklist.md`):
  - On Unix the data files (`connections.json`, `settings.json`, `vault.fernjo`, `known_hosts` and their `.bak` copies) are created with mode 0600 and a data folder fernjo creates with 0700; before, they followed the default umask. Windows ACLs are unchanged. The new tests ran green in CI on Linux (run 44218999770); macOS was not run.
  - Host names that cannot be written safely to `known_hosts` (separators, whitespace, control characters) are refused before any traffic with the error `invalid_host`.
  - An oversize `vault.fernjo` (over 64 MiB) is refused as unusable instead of being read whole, and is never overwritten.
  - Importing a hostile mRemoteNG file is bounded: too many attributes or namespace declarations are refused (`too_complex`), long names are shortened, over-long host names are dropped and over-long password attributes are not decrypted.
  - The folder depth limit is now enforced on every create, move and duplicate (`too_deep`), not only on import and restore, so a tree can no longer grow past what `connections.json` can be loaded from.
  - The main window refuses to navigate away from the app's own origin, so a remote page can no longer be loaded into it and never reaches the app's commands. On Windows the web view (WebView2) still sends one request for a cancelled top-level navigation and discards the answer; that is not prevented.
  - Hosts are confirmed per device: a host key that is in the synced `known_hosts` but that this device has not confirmed asks once ("Confirm and connect", "Connect once" or "Cancel") before any credential is sent. After this update every existing host asks once per device. Confirmations are kept in a device-local folder outside the synced data folder (`<OS local data dir>/fernjo-device`, `%LOCALAPPDATA%\fernjo-device` on Windows), which is created on the first save; choosing a data folder that contains it or lies inside it is refused.
  - Rollback protection for the vault: each vault file carries a generation counter and each device remembers the highest one it opened. An older `vault.fernjo` is refused after the master password proved genuine ("older than the version this device last opened"); automatic unlock never accepts it, and "Open the older vault" opens it anyway and re-stamps it. Not covered: the first open on a new device, two histories with the same generation, and devices that also run an older build (they may see repeated prompts). Existing vaults open unchanged; the first save adds the counter.
  - Automatic unlock never deletes the stored key from the OS keychain any more, and the lock note says when it did not work (damaged or incomplete vault file, or an older file). Unticking "Unlock automatically on this device" still removes the key.

### Changed

- SSH: the plain `ssh-rsa` host key algorithm (RSA over SHA-1) is no longer offered, like OpenSSH since 8.8; a server that only has a SHA-1 RSA host key can no longer be connected to (M6).
- Dependencies: russh updated to 0.65.2 (with `rsa` 0.10), which removes the `RUSTSEC-2023-0071` advisory ignore (M6).
- The gear dialog is now called "Settings" and also holds the terminal section (M4).
- Release builds strip symbols and link with thin LTO (M6).

### Fixed

- Settings dialog (M6): a late-arriving load no longer overwrites what you already typed; the "Saved" note disappears when you edit a terminal field again; a failed load of the terminal settings shows an error and keeps Save disabled; Enter in a terminal field no longer saves while an input method composition is active.
- Windows installer (M6): `fernjo_<version>_x64-setup.exe` now carries the fernjo app icon instead of the generic NSIS icon.
